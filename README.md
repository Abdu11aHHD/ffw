# عضيد · Adheed

واجهة التيم المبنية بـ React + TypeScript + Vite، مع ميزة عضيد داخل **ملفي** وخادم Python/FastAPI فعلي لقراءة تقارير السكر والنتائج وطلبات المتابعة. الواجهة نفسها تعرض الميزة مباشرة؛ لا iframe ولا تطبيق منفصل ولا تبويب خامس.

نموذج أولي مستقل، غير مرتبط بصحتي أو بأي مقدم رعاية. الحسابات والملفات المرفقة للتجربة اصطناعية. قرارات المراجع والمواعيد محاكاة، ولا تصل إلى طبيب أو تحجز موعدًا حقيقيًا.

## تشغيل محلي

Python 3.12 وNode 20+.

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements-dev.txt
Copy-Item .env.example .env
.\.venv\Scripts\python -m uvicorn app.main:app --host 127.0.0.1 --port 8001
```

في طرفية ثانية:

```powershell
cd web
npm install
npm run dev
```

الواجهة: http://127.0.0.1:5174 · توثيق API: http://127.0.0.1:8001/docs.
إذا كنت تستخدم pnpm فملف `pnpm-lock.yaml` مثبت في المستودع، ويمكن تشغيل `pnpm install --frozen-lockfile` و`pnpm build`.

على macOS/Linux استخدم `.venv/bin/python`. يتضمن تثبيت Windows مكتبات MSVC المحلية اللازمة لـPyMuPDF؛ لا تُنسخ DLLs أو البيئات الافتراضية إلى Git.

## رحلة التجربة الكاملة

1. ملفي ← عضيد ← الدخول كمريض تجريبي.
2. ابدأ بتقرير السكر، ونزّل ملف PDF الاصطناعي من شاشة الرفع ثم ارفعه.
3. تظهر نسبة انتقال الملف الحقيقية، ثم حالة معالجة الخادم. افتح التقرير بعد تأكيد اكتماله.
4. راجع الفترة والمؤشرات والتحقق ومصدر كل قيمة. القيم المفقودة لا تُستبدل بأصفار. القيم التي تحتاج تأكيدًا تُراجع قبل اعتمادها.
5. افتح الاستعداد لموعدي، وراجع المؤشرات وحدود البيانات والأسئلة والمقارنة إن كانت الفترات والوحدات متوافقة.
6. أرسل طلب متابعة بسبب واضح، واختر مشاركة المؤشرات أو عدم مشاركتها.
7. افتح `/reviewer`، وادخل كمراجع تجريبي، ثم افتح الطلب وابدأ المراجعة وسجّل السبب والقرار.
8. الموافقة تنشئ موعدًا تجريبيًا واحدًا؛ طلب استكمال البيانات أو عدم الحاجة لإجراء لا ينشئ موعدًا.
9. ارجع لجلسة المريض: يظهر القرار والموعد في المواعيد والتنبيهات. إعادة فتح الصفحة لا تُنشئ إشعارات مكررة. تُحدّث البيانات عند عودة التركيز إلى النافذة.

تُحفظ جلسات API في sessionStorage لكل تبويب، ليمكن اختبار دوري المريض والمراجع في نافذتين. تبديل الملف التجريبي في واجهة التيم لا يمنح صلاحية API أو يغيّر الحساب المصادق عليه. بيانات العرض داخل ذاكرة الخادم، وتزول عند إعادة تشغيله.

## التحليل الفعلي وDeepSeek

التحليل الرقمي في Python: PyMuPDF يستخرج نص PDF، والمحلل يتعرف على الملخصات المدعومة ويتحقق من المؤشرات واتساقها ويطبق قواعد مرجعية موثقة. يُحفظ مصدر الصفحة والنص والوحدة وحالة التحقق. المرجع المتحقق منه أساسًا هو ملخص Omnipod Discover؛ الأنماط العامة الأخرى تُوسم كغير متحقق من تنسيقها. لا OCR ولا إعادة بناء لنوبات زمنية من نسب إجمالية.

`AI_PROVIDER=deepseek` يستخدم `deepseek-flash` في وضع التفكير `high` لتفسير المؤشرات الموثقة ونتائج القواعد وإنتاج ملخص عربي وملاحظات وأسئلة وحدود للتحليل. يرسل الخادم قيمًا منظمة فقط، دون PDF أو اسم الملف أو الهوية أو مقتطفات المصدر. لا يُخزن سجل التفكير ولا يعرضه.

يُطلب JSON محدد وتتحقق منه Pydantic، مع فحص الأرقام والمصادر والصياغة. لا يغيّر الموديل المؤشرات أو نتيجة القواعد أو قرار المراجع. عند غياب المفتاح أو نفاد الرصيد أو انتهاء المهلة أو رفض المخرج، يظهر **ملخص محلي من Python** وسبب التحول، دون ادعاء نجاح AI. اسم المزود والموديل يظهران إذا اجتاز الرد الفحوص. هذه فحوص برمجية وليست تحققًا سريريًا من صحة كل جملة.

اختير Flash لأن المهمة تفسير بيانات محددة ضمن مخطط صغير؛ يدعم التفكير ومخرجات JSON ويتيح تقييم السرعة والتكلفة قبل الحاجة لموديل آخر. حسب [التوثيق الرسمي](https://api-docs.deepseek.com/quick_start/pricing)، يشير الاسم حاليًا إلى V4.1-Flash. إعداد الموديل قابل للتغيير. لا يُنسب للموديل اعتماد طبي.

## متغيرات البيئة

توضع أسرار الخادم في `backend/.env` فقط؛ الملف مستثنى من Git. لا تضع مفتاحًا في متغير يبدأ بـ`VITE_`.

| المتغير | الاستخدام |
|---|---|
| `AI_PROVIDER` | `deepseek` أو `gemini` أو `local` |
| `DEEPSEEK_API_KEY` | مفتاح DeepSeek على الخادم |
| `DEEPSEEK_MODEL` | افتراضيًا `deepseek-flash` |
| `DEEPSEEK_TIMEOUT_SECONDS` | افتراضيًا 90 ثانية |
| `GEMINI_API_KEY`, `GEMINI_MODEL` | بديل اختياري عند اختيار `gemini` |
| `DEMO_MODE`, `ENVIRONMENT` | العرض التجريبي أو الوضع المتصل |
| `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY` | قاعدة البيانات والتحقق من الجلسات؛ service role لا يصل للمتصفح |
| `SUPABASE_REPORTS_BUCKET` | حاوية PDF خاصة، افتراضيًا `reports` |
| `STORE_REPORT_FILES` | حفظ PDF في التخزين الخاص في الوضع المتصل فقط |
| `REPORT_RETENTION_DAYS` | مهلة الاحتفاظ بملفات PDF عند تشغيل مهمة الصيانة |
| `MAX_UPLOAD_BYTES` | حد الملف، افتراضيًا 15 MiB |
| `CORS_ORIGINS` | مصادر الواجهة المسموحة |
| `VITE_API_BASE_URL` | في `web/.env` إذا كان API على مصدر منفصل |
| `VITE_PROXY_TARGET` | عنوان API للتطوير، افتراضيًا `http://127.0.0.1:8001` |

عند النشر افصل عناوين الواجهة وAPI وفعّل HTTPS؛ Vite خادم تطوير وليس نشرًا إنتاجيًا.

## Supabase

طبّق ملفات `supabase/migrations/` الأربعة بالترتيب على مشروع جديد. الأول والثاني يحفظان مخطط المشروع الأصلي وسياسات RLS. الثالث يضيف تقارير Python والتنبيهات والحاوية الخاصة. الرابع يصلح ربط معرّفات التقارير ويضيف حفظ قرار المراجع والموعد والملاحظة والتنبيهات في معاملة واحدة مع قفل وتحقق من نسخة الطلب.

أنشئ حسابات عبر Supabase Auth. المستخدم الجديد مريض تلقائيًا؛ دور `reviewer` يُسند بواسطة مدير القاعدة فقط. لا توجد ترقية دور من الواجهة. أدخل access token في شاشة الدخول المتصلة. اضبط `DEMO_MODE=false` والمتغيرات الثلاثة لـSupabase. عند غياب التهيئة يوضح الخادم والواجهة أن التشغيل تجريبي؛ لا توجد قاعدة سحابية موصولة ضمن هذه النسخة دون إعدادك.

التقارير الخاصة مقيدة بالمستخدم في Python وRLS، والعمليات الإدارية تفحص دور المراجع على الخادم. عند رفض مشاركة المؤشرات لا تتضمن استجابة المراجع تفاصيل التقرير. روابط الملفات موقّعة لخمس دقائق من endpoint مصادق يتحقق من الملكية.

لا توجد Make أو n8n أو Zapier أو وظائف Edge تشغّل سير العمل. بعض جداول/RPC المخطط الموروث موجودة لتوافق الهجرات فقط؛ التطبيق ينفذ سير العمل في Python، ولا يستخدم موصل أتمتة خارجيًا.

## الاحتفاظ والخصوصية

في العرض لا يُحتفظ بملف PDF، وتبقى النتائج في الذاكرة. في الوضع المتصل تُحفظ ملفات PDF، عند تفعيل ذلك، داخل حاوية خاصة. قد تحتوي الملفات الأصلية هوية شخصية؛ لا تُرفع ملفات حقيقية في العرض. سجلات التشغيل لا تطبع أجسام الطلبات أو المستندات أو مفاتيح الخدمات. ترسل خدمة AI المؤشرات الموثقة المحدودة فقط.

صيانة الاحتفاظ **يدوية** وليست مهمة دورية مفعلة:

```powershell
cd backend
python -m app.maintenance          # معاينة دفعة الملفات المنتهية
python -m app.maintenance --apply  # حذف ملفات PDF المنتهية فقط، مع إبقاء نتائج التحليل
```

راجع سياسة حذف البيانات في مشروع Supabase قبل استخدام بيانات حقيقية؛ الحذف من الجداول وحده لا يمسح كائنات Storage. لا يُدّعى امتثال تنظيمي أو اعتماد سريري.

`backend/app/domain` يحتفظ بقواعد التحليل، و`services` بالاستخراج وAI والتنبيهات والمواعيد، و`api` بالمسارات المصادق عليها، و`db` ببديلَي التخزين التجريبي وSupabase. في الواجهة، `src/adheed` يحتوي الميزة والعميل المعرّف بالأنواع والمراجعة؛ بقية المجلدات تحافظ على تصميم التيم. أنماط Tailwind معزولة داخل الميزة حتى لا تغير تصميم الغلاف.
